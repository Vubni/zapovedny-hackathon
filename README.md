# Метеоархив урочища «Красное»

[Личный кабинет](http://127.0.0.1:8766/account) · [Роли, вход и сохранение сессий наблюдений](docs/ДОСТУП.md)

Приложение для анализа метеонаблюдений Центрально-Лесного заповедника. В нём можно сопоставить станции и периоды, проверить полноту измерений, разобрать исходные строки и обработать собственный файл. В комплект входят архив организаторов за 1992–2025 годы и готовый индекс наблюдений.

[Открыть демонстрационный сайт](https://meteo-89-169-128-177.sslip.io/) · [Руководство пользователя](docs/РУКОВОДСТВО.md) · [Техническая документация](docs/СТЕК.md) · [HTTP API](docs/API.md)

## Быстрый запуск

Запускайте команды из корня репозитория или распакованного комплекта. Для клонирования приватного репозитория нужен доступ к нему. Комплект можно распаковать и запустить отдельно.

### Автономно с SQLite

Нужен Python 3.9 или новее. Дополнительные пакеты Python для запуска не требуются.

```sh
python3 server.py
```

Откройте [127.0.0.1:8765](http://127.0.0.1:8765/). Оставьте терминал открытым. Для остановки нажмите Ctrl+C. Другой порт задаётся через `--port`, например `python3 server.py --port 8767`. На Windows используйте `py -3`, если команда `python3` недоступна.

### Docker Compose с PostgreSQL

Нужны работающий Docker с Compose v2, Python 3 для скрипта настройки и интернет для первой загрузки образов и зависимостей.

```sh
python3 setup_compose.py --up
docker compose ps
curl -fsS http://127.0.0.1:8766/healthz
```

Откройте [127.0.0.1:8766](http://127.0.0.1:8766/). Проверка готовности должна вернуть `{"status":"ok"}`. Скрипт создаёт `.env` при первом запуске. Храните этот файл отдельно от Git. Для остановки используйте `docker compose down`. База останется в томе `pg_data`. Флаг `--volumes` удаляет его.

## Что где хранится

| Данные | Docker Compose | Автономный запуск |
| --- | --- | --- |
| Архив организаторов | ZIP в `data/` | Тот же ZIP |
| Индекс архивных агрегатов | `results/weather.sqlite` в образе, чтение | Тот же индекс с возможностью пересборки |
| Новые станции, оригиналы файлов, правки и публикации | PostgreSQL 17, том `pg_data` | `.local/observations.sqlite3` |
| Временные отчёты | Память веб-процесса | Память локального процесса |

Интерфейс использует HTML, CSS и JavaScript. Сервер в контейнере работает на Python 3.12 и Waitress, к PostgreSQL подключается через Psycopg. Порядок переноса пользовательских данных из SQLite и восстановления из дампа описан в [технической документации](docs/СТЕК.md).

## Проверка

```sh
python3 -m unittest discover -s checks
python3 -m unittest checks.check_external_fill
python3 replay_day.py results/examples/kr1-pressure-april-29-incomplete.json
```

Последняя команда сверяет контрольный день Кр1. Есть 31 пригодное измерение давления, но оно покрывает 15 часов при пороге 18. За апрель 2024 года у Кр1 пригодны 2 из 30 суток давления. У Кр2 пригодны все 30. [Методика](docs/МЕТОДИКА.md) · [Независимая сверка](results/audit/ОТЧЁТ.md)

Для браузерных проверок нужны Node.js, Playwright и Chromium. Запустите сервер и выполните команды из корня проекта.

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node checks/browser.cjs
node checks/observations.cjs
node checks/files.cjs
```

По умолчанию браузерные сценарии с внешним сервером используют порт 8765. Для Compose задайте `METEO_TEST_PORT=8766`. Сценарий файлов запускает собственный сервер с временной базой. Некоторые Python-тесты требуют отдельную PostgreSQL или инструменты проверки Excel и пропускаются без них. [Протокол выпуска](results/stack/unified-release.json)
