# Метеожурнал урочища «Красное»

Локальное аналитическое ядро для кейса 02 Центрально-Лесного заповедника. Пользователь задаёт станцию, показатель, период и шаг, получает средние, экстремумы, покрытие, отклонения и исходные сроки. Данные, сервер и расчёты работают офлайн. Сайт передан двум участникам команды в виде черновика.

**Для команды** — [распределение задач](00_Распределение.md), [описание API](docs/API.md), [примеры реальных ответов](results/examples/), [журнал](ПРОГРЕСС.md) и [место для правок](ПРАВКИ.md).

## Запуск

Потребуется Python 3.9 или новее. Для расчётов, API и проверок используются модули стандартной библиотеки. Запускайте команды из корня проекта.

```sh
python3 journal.py
python3 server.py
```

Первая команда сразу выводит годовую таблицу давления Кр1 с помесячным разбором и причинами пропусков. При первом запуске из исходников база строится из включённого ZIP автоматически. На следующих запусках сервер проверяет SHA-256 архива и базы. Вторую команду оставьте запущенной для работы сайта. Откройте [список маршрутов](http://127.0.0.1:8765/api) или [расчёт давления за 2024 год](http://127.0.0.1:8765/api/series?station=kr1&param=pressure_hpa&start=2024-01-01&end=2024-12-31&grain=month). Черновик интерфейса находится по адресу [локального сайта](http://127.0.0.1:8765/). Другой порт задаётся через `--port 8766`.

## Проверка на реальных данных

```sh
python3 journal.py --station kr1 --param pressure_hpa --start 2024-04-01 --end 2024-04-30 --grain day
python3 journal.py --station kr1 --param pressure_hpa --raw-day 2024-04-29 --json /tmp/kr1-day.json
python3 replay_day.py /tmp/kr1-day.json
python3 journal.py --station ame60 --param t_air --start 1993-02-07 --end 2020-09-20 --base-start 1992 --base-end 2006 --csv /tmp/ame60-temperature.csv
```

Для Windows в командах выгрузки можно указать `kr1-day.json` и `ame60-temperature.csv` в текущей папке. Чтобы проверить готовый результат без сервера и создания временных файлов, выполните `python3 replay_day.py results/examples/kr1-pressure-april-29-incomplete.json`.

| Действие | Проверяемый результат |
|---|---|
| Выбрать Кр1, давление, 2024, по месяцам | 11 из 12 месяцев прошли. Апрель исключён. За год проходят 334 дня по давлению и 363 дня по станции. |
| Открыть апрель и затем 29-е число | За месяц 2 из 30 пригодных суток. 29 апреля 31 пригодное значение покрывает 15 разных часов, требуется 18. |
| Сменить показатель на температуру или точку на Кр2 | У Кр1 в апреле проходят 28 суток температуры, у Кр2 — все 30 суток давления. |
| Раскрыть 1 апреля на Кр1 | Формально сутки проходят. Все 38 пригодных значений давления равны 1005,45 гПа. API возвращает сигнал для ручной проверки. |
| Сравнить поляну и поле за 2025 | Разности температур используют 361 общий день, средний суточный ход — 8 498 общих пар «дата и час». |

## Воспроизводимость

```sh
python3 build_data.py
python3 audit_quality.py --verify results/weather.sqlite
python3 verify_analysis.py
python3 replay_day.py results/examples/kr1-pressure-april-01-valid.json
```

При работающем сервере отдельно запустите `python3 check_api.py`. Он проходит обращения к HTTP API, проверяет содержимое и обновляет файлы примеров. Для перерисовки уже приложенного SVG можно выполнить `python3 plot_coverage.py` с установленной библиотекой ReportLab.

| Материал | Назначение |
|---|---|
| `data/meteo_hack_dataset.zip` | Исходный архив без изменений. Рядом лежат паспорт организаторов и их таблица покрытия. |
| `results/build.json` | Контрольные суммы, число строк по файлам и контрольный случай Кр1. |
| `results/station_coverage.csv` и `parameter_coverage.csv` | Все календарные месяцы по станциям и параметрам, включая годы без измерений. |
| `results/weather.sqlite` | Рабочие дневные и месячные агрегаты. При отсутствии файла база автоматически пересоздаётся из ZIP. |
| `results/audit/` | Пересчёт отдельной реализацией, исходные строки контрольных случаев, формулы и график. |
| `results/analysis-checks.json` | Проверка отклонений, наклона, крайних дат, круговой арифметики и сравнения точек. |
| `docs/case-2-weather.pdf`, `docs/criteria.pdf` | Официальные условие и критерии. |

## Файл, который принёс сотрудник

```sh
python3 import_station.py --station kr1 --year 2024 --input results/examples/kr1-station-2024-04-01.json --output-dir my-import
```

В примере — 48 реальных исходных строк за 1 апреля. Вместо него можно выбрать годовой CSV станции с колонками организатора или JSON-массив таких же записей. Один запуск обрабатывает один календарный год, допускаются годы вне демонстрационного архива. В отдельной папке появляются `daily.csv`, `monthly.csv`, `station_coverage.csv` и манифест с хешами. По одному дню можно получить суточный результат, апрель при этом не проходит месячное покрытие. [Готовый отчёт из примера](results/import-example/) и [проверка импорта целого года](results/import-check.json).

Этот локальный импорт создаёт отдельный отчёт. Архив, который виден в API и на сайте, привязан к версии данных организаторов. Суточный JSON из `/api/raw` — другой формат для проверки результата через `replay_day.py`.
