# От исходного срока до результата

**Источник.** 35 CSV в архиве организаторов, три ряда наблюдений в урочище «Красное». SHA-256 исходного ZIP и перечень членов архива сохраняются в `results/build.json`. Статистику считаем для одного прибора и одной точки. В сравнении двух точек используем только данные Сокол М1 за один и тот же период. Часовой пояс исходных сроков неизвестен.

## Обязательные правила кейса

1. Время разбирается точно до минуты. Дату не сдвигаем. У АМЕ-60 в 2018 году есть 4 909 записанных сроков вне обычной четвертьчасовой сетки.
2. При `dup_conflict` исключаем все строки конфликтного срока. Флаг показателя исключает только его значение. Для каждого параметра отдельно храним пригодные значения, флаги, пустые ячейки и число конфликтных строк. В календарь включаем отсутствующие даты.
3. У АМЕ-60 порог составляет 72 разных срока за день, у Сокол М1 — 18 разных часов. Полноту пересчитываем после отбора пригодных измерений параметра. У прошедшего дня среднее берём по всем его пригодным исходным значениям. Например, 38 измерений в 19 часах дают знаменатель 38.
4. Месяц проходит одновременно по двум условиям. Неполных суток не больше 10, самая длинная серия таких суток не превышает 4. Среднее месяца — среднее его пригодных суточных средних с равным весом суток. Минимум и максимум — крайние принятые исходные наблюдения за пригодные дни.
5. Декады — 1–10, 11–20 и 21-е — конец месяца. В годы с пропусками сравниваем одинаковые календарные месяцы. Указываем число лет, которые внесли пригодное значение в среднее за выбранный период.
6. АМЕ-60 и Сокол М1 не имеют времени совместной работы. При смене прибора создаётся отдельный ряд. Тренд рассчитывается внутри станции.

## Принятые командой решения

- У целиком выбранной декады выводим среднее по её пригодным суткам с числом дней в знаменателе. Отдельный порог полноты декады в кейсе отсутствует. Если границы фильтра обрезали календарный месяц или декаду, строка показывает покрытие видимого фрагмента. Для получения среднего произвольных дат используется шаг «сутки». Этот выбор предотвращает выдачу краткого фрагмента за целый календарный месяц.
- Для среднего по выборке каждому пригодному дню даём один голос. При месячном шаге берём дни только принятых месяцев. Поэтому годовой результат при шаге «сутки» может отличаться от результата при шаге «месяц». Оба знаменателя доступны в API.
- Для направления ветра из каждого угла получаем единичный вектор, суммируем векторы и берём угол результирующего. На следующем уровне веса доступных суточных направлений равны. При длине среднего вектора до 10⁻¹² направление неопределённо. Отклонение направления лежит в [−180°, 180°). Линейный наклон и экстремумы углов не выводим. В 1998 и 2021 годах у АМЕ-60 нет пригодного направления ветра.
- Для месяца отсчёт — среднее значений этого же календарного месяца за указанные годы станции. Отклонение равно наблюдаемому среднему минус отсчёт. Выбранный интервал сравнения может включать исследуемый год. Повторите расчёт с более ранними годами для сравнения с прошлым.
- Наклон ряда оцениваем отдельно от сезонного хода. Для каждого календарного месяца центрируем год и значение относительно их средних внутри группы. Общий наклон равен сумме произведений отклонений, делённой на сумму квадратов отклонений лет. Нужны минимум три пригодных года в группе. Используем только целые валидные месяцы выбранного интервала. Пропуски и изменение состава лет ограничивают интерпретацию. Наклон описывает наблюдаемый ряд, без оценки причин и статистической значимости.
- Для «поляна и поле» месяцы сравниваем по пересечению валидных температурных суток. Проверяем полноту месяца на этом пересечении. Для суточного хода сначала усредняем измерения каждой точки внутри её фактически занятого часа на конкретную дату, затем сопоставляем одноимённые часы общих валидных дат. Разность считаем как Кр1 минус Кр2. При таком подходе разные минуты опроса не создают ложных пар.
- У прошедших суток давления, где все пригодные значения точно одинаковы, выводим замечание для специалиста. Этот сигнал не меняет статистику, флаги и исходные данные. 1 апреля 2024 у Кр1 все 38 значений равны 1005,45 гПа, у Кр2 за тот же день 39 различных значений из 48. Материалы архива позволяют направить этот случай на проверку. Физическая причина по этим данным не установлена.

## Как проверить

Сборщик преобразует ZIP в дневные и месячные таблицы SQLite. Сервер читает их в режиме «только чтение». Для раскрытия конкретного дня он достаёт исходные строки непосредственно из ZIP. Независимый скрипт `audit_quality.py` пересчитывает данные из архива отдельной реализацией. `verify_analysis.py` проверяет сравнительные показатели, периоды, круговую арифметику и тренд. `replay_day.py` принимает сохранённый суточный JSON и проверяет его итоги по строкам. С параметром `--archive data/meteo_hack_dataset.zip` дополнительно проверяются имя члена архива, состав и порядок записей, физические номера строк, сроки, флаги и значения. Отчёт с конкретными значениями находится в `results/audit/ОТЧЁТ.md`.
