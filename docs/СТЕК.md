# Запуск и хранение данных

Для работы команды используйте Docker Compose. Веб-приложение принимает запросы через Waitress и записывает пользовательские данные в PostgreSQL. Автономная версия для показа жюри запускается одной командой Python. Оба режима используют один код фильтрации, расчёта графиков и публикации.

| Данные | В Docker | В автономном режиме |
| --- | --- | --- |
| Паспорта новых станций, исходные байты CSV, XLSX и JSON, подготовленные результаты, ручные правки и опубликованные строки | PostgreSQL, постоянный том `pg_data` | `.local/observations.sqlite3` или путь `METEO_OBSERVATION_DB` |
| Аккаунты и личные сессии | Глобальные таблицы PostgreSQL в томе `pg_data`. Сохранения принадлежат пользователю и центру | Основная SQLite хранит аккаунты и сохранения. Для данных дополнительных центров создаются отдельные базы рядом с ней |
| Архив организаторов 1992–2025 и индекс дневных и месячных значений | Исходный ZIP и `results/weather.sqlite` включены в образ. При запуске сверяются обе суммы SHA-256. Запросы открывают индекс только для чтения | Те же файлы. Локальный сервер может пересобрать индекс из исходного ZIP |
| Временные отчёты для просмотра | Память одного веб-процесса | Память локального процесса |

Интерфейс — статические HTML, CSS и JavaScript. Графики строятся в браузере по HTTP API. Чтение местного архива, выбор станций на локальной карте, выгрузка графиков и расчёт по опубликованным измерениям работают без внешних сервисов. Обновление внешнего прогноза и запрос внешних оценок требуют сети. Для первой сборки контейнера нужны образы Docker и пакеты Python.

## Запустить и остановить

Нужны запущенный Docker с Compose и Python 3 для скрипта настройки. Выполните команды в каталоге проекта.

```sh
python3 setup_compose.py --up
docker compose ps
curl -fsS http://127.0.0.1:8766/healthz
```

Откройте [сайт](http://127.0.0.1:8766/) или [раздел обработки файлов](http://127.0.0.1:8766/files). Исходный архив доступен гостям. Для загрузки данных и регистрации станций войдите как администратор соответствующего центра. Для создания первого общего администратора выполните `docker compose exec web python accounts.py bootstrap --email admin@example.org --name "Администратор"`. Пароль запрашивается в терминале. [Роли и личные сессии](ДОСТУП.md). При первом запуске скрипт создаёт `.env` с правами `600` и отдельными случайными паролями для приложения и администратора PostgreSQL. При повторном запуске используются те же настройки и том. Сохраните доступ к этому файлу отдельно от репозитория.

Посмотреть последние сообщения сервера можно командой `docker compose logs --tail=50 web`. Для остановки выполните `docker compose down`. Следующий запуск через `python3 setup_compose.py --up` подключит тот же том. Флаг `--volumes` удаляет базу, поэтому для обычной остановки его использовать нельзя. Для смены порта задайте `METEO_PORT` в `.env`.

## Как публикуется результат

У каждой загрузки сохраняются оригинал, подготовленная ревизия и номер подтверждённой версии. Сайт проверяет ревизию при подтверждении. Строки для графиков и номер версии записываются за одну транзакцию. Параллельные изменения упорядочиваются блокировкой PostgreSQL до завершения транзакции. Чтение внутри транзакции использует согласованный снимок. Для поиска опубликованных наблюдений есть индекс по станции и времени. Уникальные ограничения защищают идентификаторы станций и нормализованные имена от одновременной повторной регистрации.

Контейнер приложения работает под UID 10001, с файловой системой только для чтения и временным каталогом для обработки запросов. Его роль `meteo_app` владеет таблицами приложения, может инициализировать их в схеме и менять данные. Создание баз, ролей и права суперпользователя отключены. Порт базы доступен внутри сети Compose. Порт сайта опубликован на loopback. Проверка `/healthz` обращается к обеим базам и при потере соединения возвращает HTTP 503.

## Перенести прежние загрузки из SQLite

Перенос выполняется один раз в пустую пользовательскую базу PostgreSQL. Чтобы снимок включил подтверждённые изменения из WAL, используйте команду `.backup` клиента SQLite. Для окончательного переключения завершите публикации в прежнем экземпляре до создания снимка. Ниже пример для macOS и Linux. Базу PostgreSQL сначала запустите обычной командой проекта.

```sh
snapshot_dir=$(mktemp -d)
sqlite3 -readonly .local/observations.sqlite3 ".backup '$snapshot_dir/observations.sqlite3'"
docker compose run --rm -T --no-deps --user "$(id -u):$(id -g)" \
  -v "$snapshot_dir/observations.sqlite3:/import/observations.sqlite3:ro" \
  web python migrate_observations.py --source /import/observations.sqlite3
```

Утилита возвращает количество перенесённых паспортов, файлов, подтверждённых строк и ручных правок. Она проверяет структуру снимка, ревизии и согласованность публикаций. При ошибке транзакция целиком откатывается. Повторная запись в заполненную базу отклоняется. Рабочая SQLite остаётся у владельца.

## Резервная копия и проверка восстановления

Команды запускаются из каталога проекта. Выберите место с достаточным свободным пространством, доступное владельцу архива. В примере создаётся новый закрытый каталог вне проекта.

```sh
backup_dir=$(mktemp -d "$HOME/meteo-backup.XXXXXXXX")
docker compose exec -T db pg_dump -U meteo_app -d meteo \
  --format=custom --no-owner --no-acl > "$backup_dir/meteo.dump"
```

Для проверки создайте **отдельную пустую базу**. В примере имя `meteo_restore_check` должно быть свободно.

```sh
docker compose exec -T db createdb -U postgres meteo_restore_check
docker compose exec -T db psql -X -U postgres -v ON_ERROR_STOP=1 -d meteo_restore_check \
  -c 'REVOKE CONNECT ON DATABASE meteo_restore_check FROM PUBLIC' \
  -c 'GRANT CONNECT ON DATABASE meteo_restore_check TO meteo_app' \
  -c 'GRANT USAGE,CREATE ON SCHEMA public TO meteo_app'
docker compose exec -T db pg_restore -U meteo_app -d meteo_restore_check \
  --exit-on-error --single-transaction --no-owner --no-acl < "$backup_dir/meteo.dump"
```

Восстановленную копию можно открыть через второй веб-сервер. Команда работает на свободном порту 8877, Ctrl+C завершает просмотр.

```sh
docker compose run --rm --no-deps -p 127.0.0.1:8877:8877 \
  -e METEO_PORT=8877 -e METEO_DATABASE_URL=postgresql://meteo_app@db:5432/meteo_restore_check web
```

Дамп содержит пользовательские наблюдения и источники. Для восстановления на другой машине также понадобятся код или образ с архивом организаторов и настройки доступа. Регулярное копирование на другой носитель настраивается отдельно.

## Что проверено и где пределы

В отдельном комплекте Docker зарегистрировали станцию и загрузили CSV с температурами 7, 11 и −100 °C. До подтверждения график был пустым. После фильтрации и публикации он показал среднюю 9 °C. Проверка повторилась после пересоздания обоих контейнеров, затем на отдельно восстановленной базе. Совпали оригинальные байты, паспорт станции и версия публикации. Оригинал файла относится к активному заповеднику и доступен его вошедшим сотрудникам. На архиве АМЕ-60 через HTTP сверены 10 958 дат и 360 месяцев. [Архивный протокол проверки с восстановлением БД](../results/stack/verification.json). Текущие результаты для единого режима доступа и импорта находятся в [протоколе выпуска](../results/stack/unified-release.json).

Текущая конфигурация рассчитана на один экземпляр веб-сервера. После перезапуска временный Excel-отчёт можно вновь построить из сохранённого оригинала. Подтверждённые наблюдения и исходные файлы сохраняются в базе. Для нескольких веб-реплик потребуются общее хранение временных отчётов, а для публичного адреса — HTTPS-прокси с передачей исходного Host и настройкой `METEO_PUBLIC_ORIGIN`. Предельное число одновременно работающих пользователей не измерялось.
## Публичный экземпляр в Yandex Cloud

[Демонстрационный сайт](https://meteo-89-169-128-177.sslip.io/) развёрнут вручную на ВМ `meteo-archive` в зоне `ru-central1-a`. ВМ использует Ubuntu 24.04, 2 vCPU, 4 ГиБ RAM и SSD 30 ГиБ. У публичного IP динамическая привязка. После остановки и повторного запуска сверьте IP, имя на `sslip.io`, конфигурацию Caddy и `METEO_PUBLIC_ORIGIN`.

Caddy принимает HTTPS, перенаправляет HTTP и проксирует запросы на `127.0.0.1:8766` с исходным `Host`. Waitress обслуживает приложение внутри веб-контейнера. База остаётся во внутренней сети Compose. Для отдельной установки укажите в `.env` внешний адрес вида `METEO_PUBLIC_ORIGIN=https://имя-сайта` без пути.

На действующей ВМ каталог релизов находится в `~/meteo/releases`, ссылка `~/meteo/current` указывает на развернутую версию, настройки хранятся в `~/meteo/.env`. Для ручного обновления передайте на ВМ архив нужного коммита из приватного репозитория. Распакуйте его в отдельный каталог внутри `releases` с обычными правами чтения на файлы релиза. Контейнеры читают код и SQL-инициализацию от собственных непривилегированных пользователей. Файл настроек храните отдельно с правами `600`.

Из каталога нового релиза запустите Compose с тем же файлом настроек и именем проекта. На текущей ВМ команды Docker выполняются с `sudo`.

```sh
sudo python3 setup_compose.py --file "$HOME/meteo/.env" --up
curl -fsS http://127.0.0.1:8766/healthz
curl -fsS https://meteo-89-169-128-177.sslip.io/healthz
```

После обеих успешных проверок обновите ссылку `current` на новый каталог релиза. При ошибке проверьте журналы, используя те же параметры Compose.

```sh
sudo docker compose --env-file "$HOME/meteo/.env" ps
sudo docker compose --env-file "$HOME/meteo/.env" logs --tail=80 web db
sudo journalctl -u caddy -n 40 --no-pager
```

Если локальный `/healthz` отвечает, а публичный адрес недоступен, проверьте DNS, сертификат и состояние Caddy. Если веб-контейнер не проходит локальную проверку, начните с логов приложения и PostgreSQL. При первом запуске SQL-скрипт создаёт роль только на новом томе. Если инициализация прервалась, сначала установите причину по журналу базы и проверьте существующую роль. Удаление тома уничтожает загруженные наблюдения.

### CI/CD

[Workflow GitHub Actions](../.github/workflows/ci-cd.yml) запускает Python-тесты на pull request и при пуше в `main`, затем поднимает Docker Compose и проверяет `/healthz`. Шаг деплоя предусмотрен для `main` после успешных проверок и требует настройки доступа и включения `METEO_DEPLOY_ENABLED`. Этот экземпляр запущен вручную. На проверенных запусках GitHub остановил hosted runner до выполнения тестов из-за оплаты или лимита расходов, поэтому автоматический деплой сейчас выключен.
