# Запуск и хранение данных

Для работы команды используйте Docker Compose. Веб-приложение принимает запросы через Waitress и записывает пользовательские данные в PostgreSQL. Автономная версия для показа жюри запускается одной командой Python. Оба режима используют один код фильтрации, расчёта графиков и публикации.

| Данные | В Docker | В автономном режиме |
| --- | --- | --- |
| Паспорта новых станций, исходные байты CSV/XLSX, подготовленные результаты, ручные правки и опубликованные строки | PostgreSQL, постоянный том `pg_data` | `.local/observations.sqlite3` или путь `METEO_OBSERVATION_DB` |
| Архив организаторов 1992–2025 и индекс дневных и месячных значений | Исходный ZIP и `results/weather.sqlite` включены в образ. При запуске сверяются обе суммы SHA-256. Запросы открывают индекс только для чтения | Те же файлы. Локальный сервер может пересобрать индекс из исходного ZIP |
| Сессии оператора и временные отчёты для просмотра | Память одного веб-процесса | Память локального процесса |

Интерфейс — статические HTML, CSS и JavaScript. Графики строятся в браузере по HTTP API. Чтение местного архива, выбор станций на локальной карте, выгрузка графиков и расчёт по опубликованным измерениям работают без внешних сервисов. Обновление внешнего метеопрогноза и режим Яндекс Карт требуют сети. Для первой сборки контейнера нужны образы Docker и пакеты Python.

## Запустить и остановить

Нужны запущенный Docker с Compose и Python 3 для скрипта настройки. Выполните команды в каталоге проекта.

```sh
python3 setup_compose.py --up
docker compose ps
curl -fsS http://127.0.0.1:8766/healthz
```

Откройте [сайт](http://127.0.0.1:8766/) или [вход оператора](http://127.0.0.1:8766/operator). При первом запуске скрипт создаёт `.env` с правами `600` и отдельными случайными паролями для оператора, приложения и администратора базы. При повторном запуске используются те же настройки и том. Чтобы посмотреть пароль оператора на своём компьютере, выполните `sed -n 's/^METEO_WEB_OPERATOR_PASSWORD=//p' .env`. Сохраните доступ к этому файлу отдельно от репозитория.

Посмотреть последние сообщения сервера можно командой `docker compose logs --tail=50 web`. Для остановки выполните `docker compose down`. Следующий запуск через `python3 setup_compose.py --up` подключит тот же том. Флаг `--volumes` удаляет базу, поэтому для обычной остановки его использовать нельзя. Для смены порта задайте `METEO_PORT` в `.env`.

## Как публикуется результат

У каждой загрузки сохраняются оригинал, подготовленная ревизия и номер подтверждённой версии. Сайт проверяет ревизию при подтверждении. Строки для графиков и номер версии записываются за одну транзакцию. Параллельные изменения упорядочиваются блокировкой PostgreSQL до завершения транзакции. Чтение внутри транзакции использует согласованный снимок. Для поиска опубликованных наблюдений есть индекс по станции и времени. Уникальные ограничения защищают идентификаторы станций и нормализованные имена от одновременной повторной регистрации.

Контейнер приложения работает под UID 10001, с файловой системой только для чтения и временным каталогом для обработки запросов. Его роль `meteo_app` владеет таблицами приложения, может инициализировать их в схеме и менять данные. Создание баз, ролей и права суперпользователя отключены. Порт базы доступен внутри сети Compose. Порт сайта опубликован на loopback. Проверка `/healthz` обращается к обеим базам и при потере соединения возвращает HTTP 503.

## Перенести прежние загрузки из SQLite

Перенос выполняется один раз в пустую пользовательскую базу PostgreSQL. Чтобы снимок включил подтверждённые изменения из WAL, используйте команду `.backup` клиента SQLite. Для окончательного переключения завершите публикации в прежнем экземпляре до создания снимка. Ниже пример для macOS и Linux. Базу PostgreSQL сначала запустите обычной командой проекта.

```sh
snapshot_dir=$(mktemp -d)
sqlite3 -readonly .local/observations.sqlite3 ".backup '$snapshot_dir/observations.sqlite3'"
docker compose run --rm -T --no-deps --user "$(id -u):$(id -g)" \
  -v "$snapshot_dir/observations.sqlite3:/import/observations.sqlite3:ro" \
  web python migrate_observations.py --source /import/observations.sqlite3
```

Утилита возвращает количество перенесённых паспортов, файлов, подтверждённых строк и ручных правок. Она проверяет структуру снимка, ревизии и согласованность публикаций. При ошибке транзакция целиком откатывается. Повторная запись в заполненную базу отклоняется. Рабочая SQLite остаётся у владельца.

## Резервная копия и проверка восстановления

Команды запускаются из каталога проекта. Выберите место с достаточным свободным пространством, доступное владельцу архива. В примере создаётся новый закрытый каталог вне проекта.

```sh
backup_dir=$(mktemp -d "$HOME/meteo-backup.XXXXXXXX")
docker compose exec -T db pg_dump -U meteo_app -d meteo \
  --format=custom --no-owner --no-acl > "$backup_dir/meteo.dump"
```

Для проверки создайте **отдельную пустую базу**. В примере имя `meteo_restore_check` должно быть свободно.

```sh
docker compose exec -T db createdb -U postgres meteo_restore_check
docker compose exec -T db psql -X -U postgres -v ON_ERROR_STOP=1 -d meteo_restore_check \
  -c 'REVOKE CONNECT ON DATABASE meteo_restore_check FROM PUBLIC' \
  -c 'GRANT CONNECT ON DATABASE meteo_restore_check TO meteo_app' \
  -c 'GRANT USAGE,CREATE ON SCHEMA public TO meteo_app'
docker compose exec -T db pg_restore -U meteo_app -d meteo_restore_check \
  --exit-on-error --single-transaction --no-owner --no-acl < "$backup_dir/meteo.dump"
```

Восстановленную копию можно открыть через второй веб-сервер. Команда работает на свободном порту 8877, Ctrl+C завершает просмотр.

```sh
docker compose run --rm --no-deps -p 127.0.0.1:8877:8877 \
  -e METEO_PORT=8877 -e METEO_DATABASE_URL=postgresql://meteo_app@db:5432/meteo_restore_check web
```

Дамп содержит пользовательские наблюдения и источники. Для восстановления на другой машине также понадобятся код или образ с архивом организаторов и настройки доступа. Регулярное копирование на другой носитель настраивается отдельно.

## Что проверено и где пределы

В отдельном комплекте Docker зарегистрировали станцию и загрузили CSV с температурами 7, 11 и −100 °C. До подтверждения график был пустым. После фильтрации и публикации он показал среднюю 9 °C. Проверка повторилась после пересоздания обоих контейнеров, затем на отдельно восстановленной базе. Совпали оригинальные байты, паспорт станции и версия публикации. Для гостя исходник по-прежнему закрыт, оператор после входа может его скачать. На архиве АМЕ-60 через HTTP сверены 10 958 дат и 360 месяцев. [Протокол проверки](../results/stack/verification.json).

Текущая конфигурация рассчитана на один экземпляр веб-сервера. Перезапуск завершает сессии оператора и срок действия временных ссылок на просмотр отчётов. Подтверждённые наблюдения и исходные файлы сохраняются в базе. Для нескольких веб-реплик потребуются общее хранение сессий и временных отчётов, а для публичного адреса — HTTPS-прокси с передачей исходного Host и настройкой `METEO_ADMIN_ORIGIN`. Предельное число одновременно работающих пользователей не измерялось.
