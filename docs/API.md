# API Метеоархива

При запуске `python3 server.py` из корня базовый адрес — `http://127.0.0.1:8765`. Стандартный порт Docker Compose — `8766`. Главная страница отображает наблюдения. Кабинет открывается на `/account`, работа с файлами центра — на `/files`, прогноз — на `/forecast`. Подробный разбор исходного архива находится на `/journal`. [Роли и создание первой учётной записи](ДОСТУП.md)

## Доступ и личные сессии

Без входа наблюдения, карта, покрытие и исходный журнал используют только архив организаторов. После входа графики, паспорт станции и история файлов относятся к активному центру. В Центрально-Лесном заповеднике графики учитывают также подтверждённые импорты этого центра. Подробный журнал `/api/series`, `/api/raw`, архивные выгрузки, `/api/compare`, `/api/events` и совместимый `/api/import` относятся к Центрально-Лесному заповеднику. В остальных центрах эти архивные маршруты возвращают HTTP 404.

Для `/api/files*`, `/api/review*` и изменения рабочих данных нужен вход. Без действующей сессии закрытый запрос возвращает HTTP 401, при недостатке прав — HTTP 403. Исследователь может читать файлы своего центра, создавать черновик из наблюдений, рассчитывать предпросмотр и выгружать рабочий результат. Регистрация станций, загрузка файлов и исправлений, подтверждение и снятие публикации, а также `/api/import` требуют администратора центра или глобального администратора. Браузер отправляет запросы записи с адреса Метеоархива.

| Маршрут | Тело и результат |
|---|---|
| `GET /api/account/me` | `user`, `center`, `centers`. У гостя `user: null` и публичный центр. Глобальному администратору доступны все центры. |
| `POST /api/account/login` | JSON с `email` и `password`. Возвращает контекст аккаунта и устанавливает cookie `meteo_account`. |
| `POST /api/account/logout` | JSON `{}`. Завершает текущий вход и очищает cookie. |
| `POST /api/account/centers` | Глобальный администратор отправляет `name`. HTTP 201 и новый `center`. |
| `POST /api/account/select-center` | Глобальный администратор отправляет `center_id`. Возвращается обновлённый контекст входа. |
| `GET /api/account/users` | Администратор получает список пользователей активного центра. |
| `POST /api/account/users` | JSON с `name`, `email`, `password`, `role` и `center_id`. Глобальный администратор создаёт `center_admin` выбранного центра. Администратор центра создаёт `researcher` своего центра. HTTP 201 и `user`. |
| `GET /api/account/sessions` | Список личных сессий текущего центра в поле `sessions`. |
| `POST /api/account/sessions` | JSON `{"name":"Апрель","state":{"workspace":"/observations?stations=kr1&charts=pressure&grain=month"}}`. HTTP 201 и `session`. |
| `GET /api/account/session?id=…` | Возвращает `session.state.workspace` для восстановления фильтров. Для другого владельца или центра возвращает HTTP 404. |
| `POST /api/account/sessions/delete` | JSON с `id` своей сессии в активном центре. |

`state.workspace` хранит адрес текущих наблюдений в пределах приложения. Допустимые настройки включают `stations`, `start`, `end`, `intervals`, `grain`, `mode`, `charts`, `calendar`, `coverage`, `coverageParameter`, `indicators` и `presentation`. При открытии сессии заново запрашиваются данные текущего центра.

## Наблюдения, станции и подтверждённые файлы

| Действие | Запрос | Результат |
|---|---|---|
| Узнать общий диапазон и доступные датчики | `GET /api/stations` | `stations` с кодом, подписью, параметрами, цветом ряда, типом местности `terrain`, датами, типом привязки и координатами. У гостя в каталоге только архивные станции. Для вошедшего пользователя общие границы `start` и `end` учитывают опубликованные импорты активного центра. |
| Завести станцию | Администратор отправляет `POST /api/stations` с JSON, например `{"label":"Лесной кордон","latitude":56.47,"longitude":32.98,"params":["t_air","rh"]}` | HTTP 201 и объект `station`. Координаты задаются вместе в полях `latitude`, `longitude`. Свой идентификатор, порог пригодности суток и шаг учёта покрытия можно передать полями `id`, `minimum_slots`, `slot_minutes`. |
| Получить карточку сравнения | `GET /api/observations?stations=kr1,kr2&chart=temp_difference&start=2025-01-01&end=2025-12-31&grain=month` | Отдельные ряды и Кр2 − Кр1 по общим наблюдениям. Точки содержат интервал и значение, `null` означает пропуск. В `coverage` передаются числитель, знаменатель и причина ограничения для каждого параметра. Числовая сводка `statistics` включает `years`, число лет с пригодными сутками. |
| Сравнить несколько периодов | `GET /api/observations?stations=kr1&chart=air&intervals=2024-02-28:2024-02-29,2024-04-01:2024-04-05&grain=day` | До 12 непересекающихся интервалов. Смежные периоды сохраняются отдельно. Серии и числовая сводка разделены по периодам. |
| Последние пять суток | `GET /api/observations/latest-five?station=kr1&param=t_air` и `/api/observations/latest-five.csv` | Последние календарные сутки до фактического измерения включительно. Неполные дни показаны без официального среднего; измеренные и оценённые сроки подсчитаны отдельно. |
| Получить матрицу покрытия | `GET /api/observation-coverage?stations=kr1&intervals=2024-02-28:2024-02-29,2024-04-01:2024-04-05&parameter=all` | Станции по строкам, календарные месяцы или годы по столбцам. Знаменатель учитывает только выбранные сутки. |
| Получить историю и методы обработки | `GET /api/files` | Список файлов и доступные методы, включая дополнительные фильтры и способы заполнения пропусков. |
| Взять сохранённые наблюдения для обработки | `POST /api/files/from-observations` с JSON, например `{"station":"kr1","param":"t_air","start":"2024-04-01","end":"2024-04-02"}` | Запись в очереди обработки с происхождением исходных данных. Публикация выполняется отдельно. |
| Сохранить оригинал | `POST /api/files/upload?station=kr1&filename=поляна.csv` | Тело — исходные байты CSV, XLSX или JSON. В ответе есть уникальный `id`, период или ошибка конкретного файла. |
| Проверить файл | `POST /api/files/preview` | Передайте `id`, `station`, `filters` и независимые `fill_external`, `fill_model` (0 или 1). В ответе есть версия предпросмотра, отмеченные ячейки и графики проверки. |
| Скачать и повторно загрузить ручную правку | `GET /api/files/csv?id=…&revision=…`, `POST /api/files/corrected?id=…&revision=…&filename=…` | CSV той же схемы и сроков. Загрузка создаёт новый черновик с родительской версией. Для публикации передайте новую ревизию в confirm. |
| Опубликовать | `POST /api/files/confirm` | Передайте идентификатор, актуальную `revision` и те же настройки. Публикация атомарно заменяет предыдущую обработку этого файла. |
| Получить результат или исходник | `GET /api/files/preview?id=…`, `/api/files/excel?id=…`, `/api/files/original?id=…` | Текущий расчёт, рабочая книга XLSX или исходные байты. |
| Снять опубликованную версию | `POST /api/files/discard` | Идентификатор и актуальная `version`. Исходник сохраняется, графики пересчитываются. |

Поле `terrain` принимает `clearing` (поляна), `field` (поле), `forest` (лес), `wetland` (болото), `settlement` (населённый пункт), `other` (другая местность) и `unknown` (тип не указан). Если поле пропущено, каталог возвращает `unknown`. Тип местности задаёт цвет маркера карты. Поле `color` задаёт цвет ряда наблюдений.

Маркеры карты используют каталог `/api/stations`. Для архивных станций районная привязка отмечается `location_precision=area`, а точная привязка пользовательской станции — `exact`. Станция без координат остаётся доступна в каталоге и графиках.

Для карточек поддерживаются группировки `day`, `decade`, `month`, `year` и режимы `modern`, `togu`, `semenov`. Период включительный, одинаковый для всех выбранных станций. Для внешней сверки нужны часовой пояс `timezone` и координаты станции или района архива. Для давления у поверхности укажите `pressure_reference=surface`. Пригодные модельные оценки показываются отдельным рабочим рядом с полем `role=estimate`. Полнота наблюдений, тренд и парное сравнение рассчитываются по измерениям.

Для карточки `air_anomaly` параметр `baseline=1992-2006` задаёт отдельный период отсчёта. По умолчанию отсчёт берётся из выбранных интервалов. Сопоставляются одинаковые календарные дни, декады или месяцы. У каждой точки есть `baseline` и `years` с числом лет, которые дали именно её отсчёт.

При совпадении станции и срока учитывается последняя подтверждённая версия для каждого заявленного параметра. Импорт одной температуры сохраняет измерения давления и ветра в тот же срок. Явно пустая или отбракованная температура остаётся пропуском. При снятии версии снова действует предыдущий подтверждённый источник или исходный архив.

Рабочий параметр `pressure_max` принимает `1050` (по умолчанию) и `1550` гПа. При расширенной границе подтверждённое измерение 1100 гПа без исходного флага может появиться на общих графиках. Официальный архивный журнал использует 1050 гПа. Рабочая книга Excel доступна в редакторе выбранного файла на `/files`. Запрос `POST /api/review?file_id=…&param=t_air` с пустым телом читает исходные байты на сервере и учитывает паспорт соответствующей станции. Ручные решения в скачанной книге действуют в этой копии Excel.

| Раскрыть апрель по суткам | `/api/series?station=kr1&param=pressure_hpa&start=2024-04-01&end=2024-04-30&grain=day` | `kr1-pressure-april-days.json` |

### Ряды и фильтры

Для маршрута `/api/series` доступны архивные станции `ame60`, `kr1`, `kr2`. Допустимые параметры есть в `stations[].params`. Поля `start` и `end` включительны, формат ГГГГ-ММ-ДД. Шаг `grain` принимает `day`, `dekad`, `month`. Для сравнения по календарным месяцам можно указать целые годы `base_start`, `base_end` в пределах выбранной станции. По умолчанию используются все годы этой станции. Ошибка фильтра возвращает HTTP 400 и JSON с полем `error`.

| Поля ответа ряда | Смысл для интерфейса |
|---|---|
| `unit`, `label` | Единица и название. Числа округлять только при показе. |
| `rows[].start,end,label` | Границы периода для следующего запроса и готовая подпись. |
| `valid,reason` | Принят ли период и почему. В исключённом периоде средние и экстремумы равны JSON `null`. Показать разрыв на графике и объяснение в таблице. |
| `mean,min,max` | Среднее и экстремумы в единицах показателя. У направления ветра экстремумы пусты. |
| `valid_days,days,longest_gap` | Число пригодных суток, календарных суток и максимальная длина серии неполных суток. |
| `n,flagged,missing,conflicts` | В строке таблицы `n` означает количество пригодных значений до проверки полноты суток. Отдельно даны флаги выбранного параметра, пустые ячейки и строки конфликтов. |
| `baseline,years,anomaly` | Среднее того же календарного месяца за выбранные годы, число действительно вошедших лет и отклонение. Имеют содержательный смысл при шаге «месяц». |
| `stats.valid_days,stats.used_days` | За 2024 год по давлению Кр1 проходят 334 суток. Из них 332 входят в итог при месячном шаге, так как два пригодных апрельских дня относятся к исключённому месяцу. |
| `stats.n,stats.years` | Число исходных значений из допущенных суток и число календарных лет, давших среднее. |
| `stats.trend,trend_unit,trend_n` | Наклон в единицах показателя за год и число вошедших месяцев. При недостатке лет наклон пустой. |

### Исходный день

`rows[].time` — текстовая отметка исходной станции. `value` сохраняет значение, в том числе помеченное. `flags` — исходная строка флагов, `status` — пригодность выбранного показателя в записи. `line` — номер строки исходного CSV с учётом заголовка. `source` указывает член ZIP. `n` считает пригодные измерения, `slots` — покрытие параметра, `station_slots` — покрытие станции. `threshold`, `valid`, `mean` показывают решение. Массив `signals` содержит замечания для ручной проверки. Например, у давления Кр1 1 апреля 2024 все 38 пригодных измерений одинаковы. Это замечание сохраняет исходные флаги и правило принятия дня.

### Сравнение точек

В `months` поле `pairs` означает общие валидные даты, в `hours` — общие пары «дата и час». `delta = kr1 − kr2`, единица °C. Положительная разность означает более высокую температуру на поляне. Время соответствует записям станции. Часовой пояс не установлен.

Для повторения проверок при запущенном сервере выполните `python3 check_api.py`. Скрипт заново сохранит ответы в `results/examples/`.

### Локальный импорт в браузере

`GET /import` и `GET /import.html` перенаправляют на `/files?source=upload`. Гость видит приглашение войти через `/account`. Администратор активного центра может добавить CSV, XLSX или JSON в очередь. Для совместимого отдельного расчёта служит `POST /api/import` с CSV или JSON размером до 5 МиБ. Запрос требует входа администратора Центрально-Лесного заповедника. `GET /api/import/example` отдаёт публичный пример 48 сроков Кр1 за 1 апреля 2024 года. В строке запроса передаются `station`, `param`, `year`, `grain` (day/month), по необходимости `start` и `end`. Тип тела — `text/csv` или `application/json`. Результат содержит статистику, строки таблицы и текст CSV. Неверный срок возвращает номер строки или элемента. Совместимый расчёт возвращается отдельно от очереди и исходного архива.

## Дополнительные выборки для специалиста

- `GET /api/export/latest-five?station=ame60&param=t_air` возвращает CSV с пятью календарными днями по последний день с исходными записями станции включительно. Для АМЕ-60 это 2–6 ноября 2021 года, для Кр1 и Кр2 — 27–31 декабря 2025 года. Пропуски и флаги выбранного показателя сохраняются. Обычная кнопка «Скачать CSV» по-прежнему выгружает выбранный на экране период.
- `GET /api/events?station=all&start=2024-04-01&end=2024-04-30` возвращает события смены знака среднесуточной температуры. Для одной станции замените `all` на `ame60`, `kr1` или `kr2`. По адресу `/api/events/export` с теми же параметрами доступен CSV. [Методика, реальные примеры и проверка исходных CSV](../results/research/ПЕРЕХОДЫ-ЧЕРЕЗ-НОЛЬ.md).
- Страница `/forecast` запрашивает трёхдневный региональный прогноз из браузера. Запрос выполняется на публичный API Open-Meteo. Локальная датированная копия доступна по `/forecast-example.json`.

## Рабочий расчёт и книга

Эти маршруты требуют входа. Токен расчёта действует внутри центра, в котором был запрошен.

| Маршрут | Параметры и результат |
|---|---|
| `POST /api/review` | Для архива отправьте пустое тело. Для нового файла укажите `filename` и передайте тело UTF-8 CSV, JSON или XLSX в его исходном формате. Обязательный для осмысленного выбора контекст — `station` и `param`. Даты `start`, `end` включительные. Для файлов без выбранных дат используется период записей. Можно выбирать несколько лет. Детальная книга рассчитана на 60 000 исходных строк, загружаемый файл — до 12 МиБ. |
| Числовые границы | `ranges={"t_air":[-40,42]}`, `thresholds={"spike":{"t_air":4}}`. В JSON запросов обработки передавайте объекты, в строке запроса подробного расчёта — JSON-текст. Метаданные и стандартные пороги публикует `GET /api/meta` в поле `quality`. |
| Рабочие фильтры | `filters=conflicts,hampel,spike,stuck` допускает любое подмножество. Пустой список и отсутствие параметра включают только базовый режим. `conflict_policy=all\|best` применяется при включении конфликтов, `pressure_max=1050\|1550` при выборе давления. |
| Заполнение | `fill_external=1` и/или `fill_model=1`. `fill_start` и `fill_end` ограничивают заполнение внутри исходного периода. Для внешней сверки требуется `timezone` в UTC или формате IANA, например `Europe/Moscow`, и период до 31 дня. Для давления нужно `pressure_reference=surface`. `subhour=interpolate` разрешает интерполяцию в существующих минутных строках. По умолчанию `subhour=skip`. Локальная модель оценивает значение по пригодным соседям. Внешние источники используются для сверки. Небольшая поправка допустима только при подтверждении пользы на предыдущих сроках. Источники и привязка по времени сохраняются. |
| `GET /api/review?token=…&offset=100` | Отдаёт следующие 100 строк того же расчёта. Ответ содержит `counts`, `summaries.daily`, `summaries.monthly`, `total_rows`, зафиксированные параметры и `original_workbook`. Время жизни в памяти после последнего обращения 30 минут, более раннее вытеснение возможно по объёму. Для вытесненного расчёта возвращается HTTP 410. |
| `GET /api/review.xlsx?token=…` | Полная редактируемая книга рабочего расчёта, включая исходные поля. |
| `GET /api/review-original.xlsx?token=…` | Для входного XLSX возвращает копию с динамической подсветкой в исходном листе и рабочими листами. При ограничении формата исходной книги отдельный Excel-отчёт остаётся доступен. |

Обработка измерений находится на `/files`, трёхдневный прогноз Open-Meteo — на `/forecast`, почасовая карта осадков — на `/precip`. Диапазон обзорного журнала `/api/series` охватывает всё время работы выбранной станции.
